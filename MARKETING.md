## Rule
Before creating marketing, read PRODUCT.md, ENGINEERING.md, CHANGELOG.md, and this file. Market what actually exists; do not imply unfinished features are live.

## Core message
Agent Spend gives companies visibility and control over how autonomous AI agents spend money.

## Simple description
Spend management for AI agents.

## Audience
Primary early audience:
- AI-agent builders
- Tempo ecosystem builders
- Crypto / stablecoin payment teams
- Founders building autonomous software

Primary channel: X.

## Positioning
Do not position Agent Spend as another crypto wallet or generic dashboard.

Position it as the financial control layer for autonomous software:
- See what agents spend
- Know where the money went
- Understand which agent spent it
- Enforce company-controlled permissions through Tempo
- Add approvals and richer controls over time

## Content pillars
1. Building in public — real product progress and demos
2. Agent economy — why autonomous software needs financial controls
3. Tempo — practical examples of access keys and programmable payments
4. Product visuals — dashboard screenshots, flows, feature launches
5. Founder perspective — short observations and lessons from building

## Visual system
ComfyUI is the visual production engine. Use it for high-quality supporting graphics, not random AI art. Product UI/screenshots should remain the hero whenever possible.

## Marketing loop
Product ships → CHANGELOG.md updated → identify story → create post → create visual if useful → publish on X → learn from response.

## What's live (safe to market, as of 2026-09-30)
- See every agent's spend and live on-chain budget, with no agent integration.
- Every payment can explain itself: signed reasons, cryptographically linked to the on-chain payment and marked Verified.
- Agents that hit their limit ask a human for more; approving raises the limit on-chain. One-click revoke.
- Works with any MCP agent (Claude, etc.) via the Agent Spend MCP server.
- Validated live on Tempo testnet (Moderato) for indexing + payments; control-plane actions demoed on the local fixture (live testnet validation of admin-key controls is next — don't claim it yet).

## Guardrails
- No fake traction or metrics
- No claiming unfinished features are available
- Avoid jargon when a simple explanation works
- Product credibility matters more than posting volume
